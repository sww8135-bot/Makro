# ระบบจัดการตารางเวลาและกะการทำงาน (Makro Shift Planner)

Web App แบบ Static (HTML + Tailwind CSS + JavaScript ล้วน) ไม่ต้องมี Backend และไม่ต้อง Build
ข้อมูลเก็บใน LocalStorage ของเบราว์เซอร์

## โครงสร้างโปรเจกต์

```
makro-shift-scheduler/
├── index.html      # หน้าหลัก: ตารางรายวันของเดือน
├── admin.html      # หน้าตั้งค่าหลังบ้าน: จัดการรูปแบบกะ
├── period.html     # หน้าปฏิทินรอบเดือน
├── js/
│   ├── store.js    # ชั้นข้อมูล (LocalStorage) + helper ที่ใช้ร่วมกัน
│   ├── app.js      # ตรรกะหน้าหลัก
│   ├── admin.js    # ตรรกะหน้าตั้งค่า
│   └── period.js   # ตรรกะปฏิทินรอบเดือน
└── README.md
```

## ฟังก์ชันหลัก

**หน้าตั้งค่ากะ (`admin.html`)**
- เพิ่ม / แก้ไข / ลบ รูปแบบกะ: ชื่อกะ, เวลาเริ่ม–สิ้นสุด, สีป้ายกะ, และตัวเลือก "วันหยุด (OFF)"
- ค่าเริ่มต้น: กะเช้า 06:00–15:00, กะบ่าย 13:00–22:00, วันหยุด (OFF)
- ดาวน์โหลด / นำเข้าไฟล์สำรอง (.json) และรีเซ็ตเป็นค่าเริ่มต้น

**หน้าหลัก (`index.html`)**
- เลือกเดือน/ปี (แสดงเป็น พ.ศ.) พร้อมปุ่มเดือนก่อนหน้า/ถัดไป และปุ่ม "ไปวันนี้"
- แสดงทุกวันของเดือนตามจริง (28–31 วัน) พร้อมชื่อวัน, ไฮไลต์เสาร์–อาทิตย์และวันนี้
- แต่ละวันเลือกกะจาก Dropdown (ดึงจากหน้าตั้งค่า) และกรอกเวลาทานอาหารได้
- โน้ตรายวัน 2 ช่อง: ✅ "วันนี้ทำอะไรสำเร็จ" (สีเขียว) และ ⚠️ "วันนี้ทำอะไรไม่ดี" (สีแดง) บันทึกอัตโนมัติขณะพิมพ์ (สูงสุด 500 ตัวอักษรต่อช่อง)
- สรุปรายเดือน: วันทำงาน / วันหยุด / ยังไม่ได้เลือกกะ
- พิมพ์ตารางได้ และล้างข้อมูลทั้งเดือนได้

**ปฏิทินรอบเดือน (`period.html`)**
- แตะวันที่ในปฏิทินเพื่อบันทึกวันที่มีประจำเดือน (แตะซ้ำเพื่อยกเลิก) บันทึกได้เฉพาะวันนี้และวันที่ผ่านมา
- คำนวณรอบเฉลี่ยและจำนวนวันเฉลี่ยจากข้อมูลที่บันทึก (ใช้ค่าที่ตั้งไว้เมื่อข้อมูลยังไม่ถึง 2 รอบ; รอบที่นอกช่วง 21–45 วันจะไม่ถูกนำมาเฉลี่ย)
- คาดการณ์ประจำเดือนครั้งถัดไป วันตกไข่ (ประมาณ 14 วันก่อนรอบถัดไป) และช่วงเจริญพันธุ์ล่วงหน้า 6 รอบ
- เป็นค่าประมาณเท่านั้น ไม่ใช่การวินิจฉัยหรือวิธีคุมกำเนิด ข้อมูลเก็บในเบราว์เซอร์เครื่องนั้นและไม่เข้ารหัส
- ไฟล์สำรอง (.json) จากหน้าตั้งค่ากะรวมข้อมูลโน้ตและรอบเดือนด้วย

## รันในเครื่อง

เปิดไฟล์ `index.html` ด้วยเบราว์เซอร์ได้เลย หรือรันเซิร์ฟเวอร์ชั่วคราว:

```bash
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

## Deploy

### GitHub Pages
1. สร้าง Repository ใหม่ แล้ว push ไฟล์ทั้งหมดขึ้นไปที่ branch `main`
2. ไปที่ **Settings → Pages**
3. ที่ **Source** เลือก **Deploy from a branch** → branch `main` → โฟลเดอร์ `/ (root)` → **Save**
4. รอสักครู่ ระบบจะให้ลิงก์รูปแบบ `https://<username>.github.io/<repo>/`

### Vercel
1. Push โปรเจกต์ขึ้น GitHub
2. เข้า [vercel.com](https://vercel.com) → **Add New → Project** → เลือก Repository
3. **Framework Preset** เลือก **Other** ปล่อย Build Command และ Output Directory ว่างไว้ → **Deploy**

หรือใช้ CLI: `npx vercel --prod` ในโฟลเดอร์โปรเจกต์

## หมายเหตุ

- ข้อมูลผูกกับเบราว์เซอร์และอุปกรณ์ที่ใช้ ไม่ซิงก์ข้ามเครื่อง ใช้ไฟล์สำรอง .json เพื่อย้ายข้อมูล
- ใช้ Tailwind ผ่าน CDN เพื่อให้ Deploy ได้ทันทีโดยไม่ต้อง Build หากต้องการใช้งานจริงระดับ Production
  แนะนำให้เปลี่ยนไปใช้ Tailwind CLI
- ปรับสีแบรนด์ได้ที่ `tailwind.config` ในส่วน `<head>` ของทั้งสองหน้า (Makro Red `#E31837`)
